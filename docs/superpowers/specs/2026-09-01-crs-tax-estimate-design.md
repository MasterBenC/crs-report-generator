# 境外投资补税测算 Skill 设计

日期：2026-09-01
状态：待用户审阅
范围：把现有 crs-report-generator 从“CRS 申报表生成器”升级为本地 Agent 上的境外投资补税测算助手

## 1. 问题与目标

真实场景不是客户自己填 CRS 表。税局通过 CRS 发现境外账户后，会要求有海外资产的中国税收居民补缴个人所得税。客户通常很小白：不知道自己是不是税收居民，也算不清要交多少税、要给税局准备什么。

本 skill 只做中介该做的事：

- 在 WorkBuddy / 豆包 Work 这类本地 Agent 里，用很短的白话问询收集必要信息
- 读取全年券商/银行结单
- 从数据表提取买入、卖出、分红、利息，完成成本匹配和年内盈亏互抵
- 给出可复核的补税测算，以及给税局的材料建议

不做的事：

- 不解释 CRS 制度，不做 CRS 问答
- 不生成可直接提交的官方 CRS XML / 官方申报表
- 不采集身份证、户口本等客户身份原件
- 不让客户回忆或估计买入价
- 不把测算结果说成税务意见或确定应纳税额

对外名称：境外投资补税测算
内部目录名可继续使用 crs-report-generator，便于旧用户升级。客户对话里不出现 CRS、TIN、金融机构编号等词。

## 2. 用户与界面

主要使用者是很小白的客户，设计假设对方可能是完全不懂税务的老年人。顾问可以使用同一套结果里的展开底稿，但默认对话只给客户看懂的四块内容。

前端不另做网站。就用本地 Agent 对话界面，例如 WorkBuddy 或豆包 Work。客户在对话里回答问题、上传结单、查看结果。

一次只问一句。看不懂可以说“我不知道”。系统能从文件里读到的，不问客户。

## 3. 问询流

默认 5 步，不问买入价。

1. 您想算哪一年的税？
   客户可以说 2024、2025，或“单子上写的哪年”。
2. 这一年您主要住在哪儿？
   选项：大部分时间在国内 / 国内国外两边跑 / 基本上住在国外 / 我也不清楚。
   若选两边跑或住国外，再追问：这一年在中国住满半年了吗？家里是不是还在国内？
   系统据此判断是否按中国居民个人测算。不确定时，按“先当要在中国交税”计算，并明白告诉客户：这是先按国内交税准备；如果其实长期住在国外，数字可能会变。
   不使用“税收居民”这个词。
3. 钱放在哪几家了？
   可以说“富途那个”“华泰那个”，也可以不说，直接上传结单让系统识别。
4. 把这一年能找到的月结单、年结单都传上来。
   能找到多少传多少。系统负责按人、账户、年份归堆，不让客户自己分类。
5. 这一年有没有分过红、收过利息，或者外国已经扣过税？
   不知道就说不知道。有对应页面就一起上传。

禁止问：

- 是不是中国税务居民
- TIN / 身份证号
- 买入价、成本、汇率
- 金融机构编号

## 4. 材料处理

输入是全年、多券商、多账户、多币种的结单，不是单张 PDF。

解析策略是“通用提取 + 已验证模板”：

- 先按关键词识别券商
- 已验证模板优先：第一版沿用现有华泰解析器
- 富途、盈透、辉立等随后补模板
- 识别不出或版式不支持时，不卡死。改为提取能读到的表格字段；仍不够则列出缺口，让客户补该年年末市值、买卖记录、分红页。仍然不让客户填买入价。

每份文件先做识别，再抽取原始证据，再标准化字段。每个金额和交易必须保留来源文件、页码或表格位置、原文、标准化值和置信度。

字段冲突时保留冲突，不自动选一个看起来合理的值。扫描件或图片 PDF 第一版可提示“这张单子系统读不清，请换文本版结单或把关键页补充进来”。

## 5. 成本匹配

买入价只能从结单、成交表、资金变动、持仓变动里读取。

匹配顺序：

1. 按账户、日期整理该年全部结单
2. 抽出买入、卖出、数量、价格、费用
3. 同一证券先配当年买入；当年买不够，再往更早的结单里找
4. 配得上的，才计算该笔卖出盈亏，进入年内互抵
5. 配不上的，不编买入价，不按现价或均价倒推，整笔标成“还缺买入记录”，不计入确定税额

禁止：

- 让客户回忆买入价
- 用现价、均价或估算成本代替
- 把配不上的卖出当作收益

## 6. 所得分类与盈亏互抵

针对中国居民个人、综合所得场景的常见境外金融账户。

分类：

- 分红、利息：单独计算，不能用亏损冲掉
- 已经卖掉的股票、基金等：按财产转让，先配成本，再做同一年内盈亏互抵
- 没卖掉的市值变动：不算税

互抵规则：

- 只有该年已卖出且成本匹配成功的盈亏可以对冲
- 互抵后大于 0，才进入计税；小于 0，这一块按 0
- 亏损不冲分红和利息
- 亏损不结转到下一年
- 外国已扣税只从对应收入里抵，不冲买卖亏损

汇率从结单当天或结单标明的汇率转为人民币。当天没有则用该月公开汇率，并在底稿写明来源日期和数值。不问客户汇率。

客户可见结果拆成三行：

- 分红和利息：多少钱，大概交多少
- 卖掉的股票基金：赚的减去亏的之后还剩多少，大概交多少
- 还没配上买入记录的卖出：暂时不算，标成单子还不全

“大概要补多少”只加前两行里能确定的数。缺单子的部分不估、不计入确定总额。

结果同时保留互抵后和不互抵两个数，供顾问核对。默认只给客户看互抵后的人话结果。

## 7. 输出

默认对话只显示四块：

1. 大概要补多少钱：一个确定数，或在材料不全时只给已确定部分，并列出暂不算的交易
2. 这钱是怎么来的：分红、卖掉后互抵、外国已扣税抵了多少。互抵说成“亏的减赚的”
3. 还缺哪些单子：缺哪家、缺哪几个月、缺哪几笔买入记录。说明“有了会更准，没有这些笔先不算”
4. 给税局准备什么：按年份归好的结单、测算表、缺材料说明。身份证只提示客户自己带去税局或交给中介，系统不收、不存、不要上传

顾问可展开的底稿：

- 账户盘点
- 全年交易与成本匹配
- 盈亏互抵过程
- 所得分类与测算
- 证据索引
- 原始提取 JSON

不把 CRS 申报表、TIN 填写页、内部 JSON 作为给税局的材料。

给税局的建议材料：

- 境外账户该年结单，按券商和年份分开
- 测算表：分红、已匹配卖出盈亏、互抵净额、建议补税
- 缺材料说明：哪些卖出因缺少买入记录暂未计入

系统把材料分成三个盒子：已经齐了可以交 / 还缺且会影响税额 / 有更好但没有也能先交。

## 8. 风险边界

- 所有输出都标明：这是测算底稿，不是税务意见，正式申报前需人工审核
- 不确定居民身份时，按国内交税先算，并写明这个假设
- 不处理身份证件、银行密码、验证码
- 结单和生成文件默认只留在本地 Agent 环境
- 不把无法匹配成本的交易估成税额
- 不把单张结单的当日买卖价差当成全年资本利得

## 10. 测试标准

基线失败已经能从旧版看出：把流水交易当 CRS 申报内容、默认 HKD、把卖出总额叫收益、让客户补 TIN、单张结单生成一张美化表。

升级后至少覆盖这些合成案例：

- 同一年两只股票，一赚一亏，确认只对已匹配卖出互抵，分红不被亏损冲掉
- 只有卖出没有对应买入，确认该笔不计入确定税额，并出现在缺材料清单
- 多份月结单归堆到同一账户同一年
- 客户说不清住在哪里时，系统用白话追问，不出现“税收居民”
- 结果页不要求上传身份证，只提示自行携带
- 华泰文本结单仍能抽出账户、持仓和成交，作为解析回归

禁止用真实客户 PDF 作为仓库测试样例。只使用脱敏或合成数据。

## 11. 第一版范围

做：

- 本地 Agent 白话问询
- 全年多文件归堆
- 华泰模板 + 通用提取
- 成本匹配、年内盈亏互抵
- 客户四块结果 + 顾问底稿 + 税局材料建议

不做：

- 独立网站或云端上传
- 完整官方 CRS 报文
- 自动申报
- 身份证采集
- 买入价估计
- 所有券商一次性适配完成

后续再补富途、盈透、辉立等模板，以及更完整的居民身份判断提示。
